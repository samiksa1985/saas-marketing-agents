# Security operations runbook

Production requires OIDC, server-side RBAC, transaction-local RLS, HTTPS origins, explicit CORS origins, proxy posture, semantic release metadata, and disabled provider mutations by default. Local-acceptance authentication is rejected in production.

The API applies request IDs, no-sniff/frame/referrer/permissions headers, HSTS in production, exact origin allowlisting, sanitized JSON logging, safe health/readiness bodies, safe error bodies, and a per-process request limiter. The web server applies CSP and browser security headers. Reverse-proxy TLS, WAF/DDOS protection, distributed rate limiting, trusted forwarded-header replacement, webhook signature validation, secret manager policy, vulnerability scanning, and alert routing remain deployment-operator responsibilities.

Production PostgreSQL clients require `sslmode=verify-full` on both runtime
and migration URLs. An optional CA trust bundle is injected by file reference;
PostgreSQL server certificate/key material is external to source control and
container build inputs. The production Compose topology publishes no database
port and limits web/API host listeners to loopback behind the trusted proxy.

Never log request bodies, authorization headers, cookie values, credentials, provider tokens, or database URLs. Rotate an exposed secret in its secret manager, disable the related provider binding, and preserve an audit-safe incident record. Treat unknown provider/credential health as not mutation-ready.

## Secret inventory and injection

Keep secret values in the deployment secret manager or an operator-controlled file outside the repository. The supported `NAME_FILE` form takes precedence over `NAME`; an unreadable or empty referenced file fails closed. One final LF/CRLF is removed. Do not store production values in `.env.production`, local `.env` files, Compose interpolation, logs, manifests, SBOMs, or image build arguments. `.env.example` contains names and blank file-reference placeholders only.

| Secret                                                                                                          | Consumer/scope                                                                                                                                                                                                                                   |
| --------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `DATABASE_URL` / `DATABASE_URL_FILE`                                                                            | Runtime application role; API and worker only. Also consumed by database verification and backup/restore source checks when those operator tasks run.                                                                                            |
| `MIGRATION_DATABASE_URL` / `MIGRATION_DATABASE_URL_FILE`                                                        | Privileged migration identity for migration and role-provisioning operator tasks; the Compose migration profile only. Never expose to API or worker. Production migrations require this separate authority.                                      |
| `CODECORE_POSTGRES_PASSWORD_FILE`                                                                               | Host-side path to the PostgreSQL initialization password file; Compose mounts it read-only as `POSTGRES_PASSWORD_FILE` into PostgreSQL only.                                                                                                     |
| `CODECORE_APP_PASSWORD` / `CODECORE_APP_PASSWORD_FILE`                                                          | Role provisioning/rotation operator task; not an application runtime credential.                                                                                                                                                                 |
| `GOOGLE_ADS_DEVELOPER_TOKEN`, `GOOGLE_ADS_CLIENT_SECRET`, `GOOGLE_ADS_REFRESH_TOKEN` and matching `_FILE` forms | API Google Ads provider resolver. For file form, mount only enabled provider files read-only into API and point `_FILE` to the in-container mount. Keep mutation disabled unless the separate approval and sandbox controls authorize execution. |
| `META_ADS_ACCESS_TOKEN`, `META_ADS_APP_SECRET` and matching `_FILE` forms                                       | API Meta Ads provider resolver. For file form, mount only enabled provider files read-only into API and point `_FILE` to the in-container mount. Keep mutation disabled unless the separate approval and sandbox controls authorize execution.   |
| `LOCAL_ACCEPTANCE_AUTH_TOKEN_FILE`                                                                              | Local acceptance only; token file must be external to the repository. Local acceptance auth is forbidden in production.                                                                                                                          |

OIDC issuer, API audience, and browser client ID are configuration. The API consumes the confidential `OIDC_CLIENT_SECRET` only during server-side code exchange; inject it through `OIDC_CLIENT_SECRET_FILE` mounted read-only to the API service. The web service never receives it. Authorization codes, PKCE verifiers, state, nonce, access/ID tokens, session cookies, and CSRF tokens must not enter application logs. Login transaction state expires after five minutes; browser sessions expire after eight hours and can be revoked by logout or tenant rotation.

Production Compose mounts the PostgreSQL password to the database container, the runtime URL to API/worker, the migration URL only to the migration profile, and the OIDC client secret only to the API service. Secret mounts are read-only. The operator must provide the `CODECORE_*_FILE` and `OIDC_CLIENT_SECRET_FILE` host paths and secure their source files with least-privilege ownership and permissions. The sample overrides secret fields inherited from its shared `.env.production` config file; keep that file non-secret. Optional provider file references are supplied to the API as in-container paths and require operator-provided read-only mounts. Unneeded provider/restore/provisioning credentials are blanked in the Compose services. The release workflow uses the `production-release` GitHub Environment: configure required reviewers and tag/deployment restrictions in repository settings. Workflow YAML alone does not establish those protections; pull requests must not receive production release authorization.

## Rotation and emergency revocation

For routine rotation, update the managed secret or external file, restart/redeploy every consumer listed above (or rerun the one-shot migration/provisioning task), and verify readiness and the relevant database/provider checks before enabling dependent execution. Database runtime-role rotation must update the role credential and runtime URL together, then restart API and worker. Migration credentials are changed and exercised only by migration or role-provisioning operator tasks, never by API/worker runtime. PostgreSQL initialization password changes do not rotate existing database role passwords automatically.

For suspected exposure, immediately disable the affected provider binding or stop the affected service, revoke/rotate the credential at its authority, replace the injected secret, and preserve sanitized audit evidence. For a database credential, rotate the database role first and update the corresponding connection URL before restoring service. Do not rely on file replacement alone for already-running processes; restart them to reload. Confirm no credential value entered source control, image metadata, release artifacts, or logs.
