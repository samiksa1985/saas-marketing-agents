# Phase 2 — Canonical Agent Registry

## Goal

Create one addressable registry without deleting the existing 71 specialist agents.

## Tiers

- CONTROL — platform execution/governance roles
- DOMAIN_LEADER — Project 2 domain heads
- SPECIALIST — Project 1 specialist workforce
- ADVISORY — non-executing advisory intelligence
- WORKFLOW — deterministic orchestration, not an LLM agent

## Imported domain leaders

- **ai-orchestrator** — CONTROL: keep separate from CATALYST; technical coordination only.
- **business-intelligence** — DOMAIN_LEADER: consolidate company intelligence ownership; do not delete specialist research agents.
- **market-research** — DOMAIN_LEADER: consolidate research synthesis; specialists remain granular.
- **marketing-strategist** — DOMAIN_LEADER: strategy synthesis over current workstreams.
- **content** — DOMAIN_LEADER: content domain owner over specialist writers/social/email/design agents.
- **campaign** — DOMAIN_LEADER: campaign planning/governance over channel specialists.
- **creative** — DOMAIN_LEADER: creative direction over design/video/creative specialists.
- **seo** — DOMAIN_LEADER: SEO/AEO/GEO synthesis over SEO specialists.
- **analytics** — DOMAIN_LEADER: growth diagnosis and prioritization over analytics specialists.
- **sales** — DOMAIN_LEADER: qualification/proposals/next-best-action over sales specialists.
- **customer-success** — DOMAIN_LEADER: lifecycle/retention/health over client-ops/customer marketing specialists.
- **automation** — CONTROL: defines automation; deterministic workflow engine owns execution.
- **cfo-intelligence** — DOMAIN_LEADER: profitability intelligence; approval required for financial actions.
- **ai-business-mentor** — ADVISORY: recommendations only; no direct execution authority.

## Safety rule

This phase deliberately does **not** auto-merge or delete any Project 1 specialist based only on names. Exact-name collisions are marked `MERGE_CANDIDATE` for later review using mission, tools, outputs, dependencies, and business value.
