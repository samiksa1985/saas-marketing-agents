# Product UX Route Manifest

All routes are implemented by the canonical `apps/web` Next.js application:
the root page for `/` and one typed dynamic surface route for the remaining
declared view identifiers. A data source marked **composition required** is an
honest unavailable state until a tenant-bound canonical composition endpoint is
provided; it is not seeded with mock data.

## Shared route contract

1. A real tenant session is required before protected canonical data is read.
2. The view model evaluates tenant context, permissions, and entitlements
   independently. A flag cannot make an unauthorized view authorized.
3. Approval state is preserved for sensitive surfaces. The frontend does not
   transform an approval into an external action.
4. Arabic uses `dir="rtl"`; English uses `dir="ltr"`. The same application
   shell and data states operate in both directions.
